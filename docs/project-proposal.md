# Her Motion — Project Proposal

## 1. Project Information
- **Course:** SW302 — User Interface Development
- **Semester:** Fall 2026
- **Project:** Her Motion — Fitness & Workout Planner
- **Team members:** Marwa, Rana, Yasmeen, Roaa
- **Current phase:** Phase 2 — UI/UX Design & Static Prototype

## 2. Project Overview
Her Motion is a proposed fitness and workout planning web application. It is designed to give users a clear place to browse exercises, understand how to perform them, organize workout routines, and review activity summaries.

The Phase 2 deliverable focuses on the user experience and a static HTML5 + Tailwind CSS prototype. The prototype will communicate the intended layout, visual hierarchy, and responsive behavior before interactive functionality is developed in later phases.

## 3. Problem Statement
People who plan workouts may need to use separate sources to find exercises, review instructions, and organize routines. This can make workout planning feel fragmented and make it harder to review activity consistently.

Her Motion aims to present these related tasks in one coherent interface.

## 4. Proposed Solution
The proposed application organizes the experience around:
- A dashboard for workout summaries and visual activity insights.
- An exercise library for browsing and filtering exercises.
- An exercise details page with instructions, target muscles, and safety guidance.
- A routine builder layout for arranging a workout plan.
- Login, registration, profile, and settings pages to represent the main user journey.

During Phase 2, these screens are static prototypes. Their controls demonstrate the intended interface but do not perform real actions.

## 5. Target Users
The intended users are people who want to plan and track fitness activities, including:
- Beginners who need a clear way to discover exercises and read instructions.
- Users who want to organize workouts into routines.
- Regular exercisers who want to review activity summaries.

These are proposed user groups and will be refined if user feedback or course guidance requires it.

## 6. Project Objectives
1. Design a consistent UI/UX for the main application journey.
2. Produce desktop and mobile mockups for at least eight key pages.
3. Build a static prototype using semantic HTML5 and locally installed Tailwind CSS.
4. Apply responsive layout techniques and accessible design practices.
5. Prepare the project structure and documentation for later React and data-integration phases.

## 7. Phase 2 Pages
The current page plan contains nine HTML pages:
- Landing / Home
- Dashboard
- Exercise Library
- Exercise Details
- Routine Builder
- Login
- Register
- Profile
- Settings

This exceeds the minimum of eight pages in the Phase 2 brief. The team should verify that each page has both desktop and mobile layouts and that the dashboard includes at least one chart or visualization.

## 8. Technology and Tools
- **HTML5:** Semantic structure for static pages.
- **Tailwind CSS:** Locally installed utility-first CSS framework; CDN use is not permitted.
- **GitHub:** Version control and collaboration.
- **Local JSON data:** Sample exercises and routines are available for later phases.
- **Figma:** UI/UX mockups and design reference.

React and interactive data handling are planned for later phases, not the Phase 2 static prototype.

## 9. Expected Phase 2 Deliverables
- Desktop and mobile wireframes/mockups.
- A static HTML5 + Tailwind CSS prototype.
- Responsive layouts for every delivered page.
- Accessibility-conscious markup, suitable contrast, and consistent spacing.
- Updated repository documentation and meaningful Git history.

## 10. Scope Limitations
Phase 2 does not include a working authentication system, real data persistence, active filters, workout timers, interactive routine management, or live API integration. These behaviors may be implemented in later phases if required by the course.

## 11. Success Criteria
The Phase 2 work will be considered ready for review when all planned pages have been implemented, each page has been checked at desktop and mobile widths, the dashboard contains a visible visualization, and the team has reviewed accessibility basics and documented the actual testing results.
